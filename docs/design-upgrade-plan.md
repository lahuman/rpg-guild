# RPG Guild Design Upgrade Plan

## 목표

- 길드 운영 툴을 "관리 화면"이 아니라 "게임 HUD + 길드 로비"처럼 느껴지게 만든다.
- 랜딩, 길드 허브, 멤버, 미션, 로그, 모달까지 하나의 시각 언어로 통합한다.
- 과한 효과보다 정보 위계를 해치지 않는 범위에서 게임형 모션을 더한다.
- Svelte + Tailwind 기반에서 유지보수 가능한 디자인 토큰과 UI 패턴을 정착시킨다.

## 현재 상태 진단

### 강점

- 전역 색상과 다크 배경은 이미 판타지/게이밍 방향에 가깝다.
- `app-panel`, `app-card`, `app-button`, `app-stat` 등 공통 패턴의 기초가 있다.
- `lucide-svelte` 기반 아이콘 사용으로 시각 언어 확장이 쉽다.
- 길드/멤버/미션/로그로 정보 구조가 명확하다.

### 문제

- 여러 핵심 화면에 머지 충돌 마커가 남아 있어 UI 일관성이 깨진 상태다.
- 화면별로 구 버전과 신 버전 스타일이 섞여 있어 비주얼 톤이 흔들린다.
- 게이밍 감성은 색과 카피에 일부 반영됐지만 모션 시스템과 상태 표현은 약하다.
- 버튼, 탭, 카드, 모달, 빈 상태, 로딩 상태가 화면별로 다른 규칙을 사용한다.
- 미션 완료, 상점 구매, 등급전 같은 "재미 포인트"가 시각적으로 충분히 강조되지 않는다.

## 디자인 컨셉

### 키워드

- Tactical Fantasy
- Guild Command Center
- Reward-driven HUD
- Arcane Glass + Metal Frame

### 비주얼 방향

- 배경은 현재 다크 톤을 유지하되, 길드 본부 느낌의 입체 레이어를 강화한다.
- 카드와 패널은 단순 유리판보다 "금속 프레임 + 룬 글로우 + 내부 노이즈" 느낌으로 발전시킨다.
- 강조색은 `amber`를 메인 보상 색으로, `cyan`을 시스템/정보 색으로, `rose`를 경고/리스크 색으로 고정한다.
- 타이포는 제목에서 더 강한 판타지/전술적 인상을 주고, 본문은 현재 가독성을 유지한다.
- 페이지마다 "월드 빌딩 문구"를 조금 넣되, 실제 관리 효율을 해치지 않도록 짧게 유지한다.

## UX 원칙

- 항상 현재 상태가 먼저 보이게 한다: 길드 상태, 멤버 수, 진행 중 미션, 최근 기록.
- 중요한 액션은 즉시 눈에 띄게 한다: 생성, 참가, 미션 완료, 구매, 저장.
- 보상/성과 이벤트는 시각적으로 크게, 관리성 작업은 차분하게 처리한다.
- 모션은 피드백을 위한 수단으로만 사용한다. 장식성 반복 애니메이션은 제한한다.
- 모바일에서도 카드 스택과 HUD 블록이 자연스럽게 읽히게 설계한다.

## 화면별 설계

### 1. 글로벌 셸

- 헤더를 "길드 네비게이션 바"가 아니라 "상단 HUD"처럼 재설계한다.
- 로고 영역은 문장형 브랜드보다 엠블럼 중심으로 강화한다.
- 사용자 프로필은 단순 계정 표시가 아니라 "현재 모험가 상태"처럼 보이게 만든다.
- 전체 배경에 미세한 그리드, 안개, 룬 파티클 같은 저강도 장식을 추가한다.

### 2. 랜딩 페이지

- 좌측 히어로는 "길드 운영 게임의 코어 루프"를 보여주는 대형 소개 블록으로 유지한다.
- 우측 로그인/참가/생성 패널은 실제 게임 로비 패널처럼 더 명확히 분리한다.
- `join/create` 토글은 탭이 아니라 모드 스위처처럼 강화한다.
- 로그인 버튼에는 시작 액션의 무게감을, 초대 코드 입력에는 긴장감을 부여한다.
- 핵심 기능 카드 3개는 단순 소개보다 "미션, 보상, 기록" 루프를 설명하는 구조로 바꾼다.

### 3. 길드 허브

- 허브 화면은 길드의 "대시보드" 역할을 분명히 해야 한다.
- 추천 구성:
  - 길드 배너
  - 핵심 스탯 바
  - 빠른 액션 패널
  - 최근 멤버 활동
  - 보상 설정/상점 진입
- 초대 코드, 길드명 수정, 설명 수정은 동일한 인라인 편집 패턴으로 통일한다.
- 상점 관리와 등급전은 보조 기능이 아니라 "재미 시스템" 섹션으로 격상한다.

### 4. 멤버 페이지

- 캐릭터 카드를 "프로필 카드"가 아니라 "파티 슬롯"처럼 강화한다.
- 레벨, 골드, 등급, 직업을 한눈에 읽히는 HUD 배치로 정리한다.
- 출석, 편집, 삭제, 상점 진입 버튼은 hover에만 숨기지 말고 모바일 대응 구조로 정리한다.
- 높은 레벨/높은 등급 캐릭터에는 차등 글로우와 배지 효과를 준다.

### 5. 미션 페이지

- 미션은 가장 게임다운 화면이므로 리디자인 우선순위를 높게 둔다.
- `solo`, `party`, `one-time` 상태를 배지와 카드 프레임으로 즉시 구분 가능하게 한다.
- 미션 완료 모달은 "보상 분배 패널"처럼 강화한다.
- 랜덤 보상 상자 연출은 이 페이지의 핵심 시그니처 애니메이션으로 활용한다.

### 6. 로그 페이지

- 로그는 단순 리스트보다 "전투 기록 / 경제 기록" 타임라인처럼 설계한다.
- 날짜 구간 카드와 기록 아이템 간 대비를 높여 탐색성을 올린다.
- 미션 로그와 구매 로그의 타입 차이를 아이콘, 색상, 배지로 명확히 분리한다.

### 7. 모달 계층

- `MiniGameModal`, 상점 관리, 미션 완료, 편집 모달은 하나의 공통 모달 규칙으로 정리한다.
- 모달 오픈 시 배경 딤 + 스케일 + 블러를 동일 규칙으로 적용한다.
- 모달 헤더, 본문, 액션 푸터 구조를 통일한다.

## 애니메이션 시스템

### 목적

- 상태 변화와 보상 피드백을 더 명확히 전달한다.
- 화면이 "살아있다"는 느낌을 주되, 과한 모션으로 피로를 만들지 않는다.

### 모션 레이어

- 페이지 진입:
  - 섹션 단위 `fade + slight rise`
  - 카드 리스트 `stagger reveal`
- 인터랙션:
  - 버튼 hover 시 미세한 lift + glow
  - 탭 전환 시 active pill slide
  - 카드 hover 시 border pulse, inner sheen
- 상태 변화:
  - 저장 성공 시 brief highlight flash
  - 로딩 시 rune spinner 또는 energy bar
  - 빈 상태는 정적인 아이콘 대신 저강도 floating 모션
- 보상 연출:
  - 미션 완료 시 coin burst / stat pulse
  - 등급전 결과 시 emblem glow
  - 상자 보상 시 delayed reveal + shine sweep

### 기술 원칙

- 기본은 CSS animation + transition으로 처리한다.
- 모달/리스트/오버레이 전환은 Svelte transition을 제한적으로 사용한다.
- 반복 애니메이션은 opacity, transform 위주로 구성한다.
- `prefers-reduced-motion` 대응을 반드시 넣는다.

## 리스크

- 현재 충돌 상태를 정리하지 않고 디자인 작업을 진행하면 재작업 가능성이 높다.
- 페이지별 개별 스타일을 먼저 만지면 공통 시스템 없이 다시 분산된다.
- 애니메이션을 먼저 과하게 넣으면 성능과 유지보수성이 모두 나빠진다.

## 완료 기준

- 모든 핵심 화면이 동일한 시각 언어를 사용한다.
- 주요 액션과 상태 변화가 시각적으로 즉시 인지된다.
- 보상/등급전/상점 경험이 게임처럼 느껴진다.
- 모바일과 데스크톱 모두에서 구조가 무너지지 않는다.
- `prefers-reduced-motion` 포함, 과한 모션 없이도 분위기가 유지된다.
