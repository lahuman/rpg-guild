# RPG Guild Screen Design Brief

## 문서 목적

이 문서는 외부 디자이너 또는 디자인 에이전시에게 현재 서비스의 전체 화면 구조와 디자인 요구사항을 설명하기 위한 브리프다.
목표는 "화면을 예쁘게 바꾸는 것"이 아니라, 길드 운영 서비스를 하나의 게임형 운영 콘솔로 재해석하는 것이다.

이 문서는 다음 용도로 사용한다.

- 화면별 구조 이해
- 디자인 작업 범위 산정
- UX 우선순위 공유
- 시안 방향 설정
- 최종 산출물 기준 정의

## 프로젝트 한 줄 설명

`RPG Guild`는 길드/팀 운영을 "RPG 길드 관리 콘솔"처럼 경험하게 만드는 웹 서비스다.

사용자는 다음 행동을 수행한다.

- 길드 생성 / 참가
- 캐릭터(멤버) 등록 및 관리
- 출석 체크
- 미션 생성 / 완료
- 보상 지급
- 상점 사용
- 등급전 진행
- 활동 로그 조회

즉, 일반적인 팀 운영 도구가 아니라 `길드 운영을 게임처럼 느끼게 하는 B2C/B2B 중간 성격의 운영 툴`이다.

## 핵심 디자인 목표

### 1. 게임 감성은 강하게, 관리성은 유지

- 첫인상은 게임 HUD, 길드 로비, 전술 콘솔에 가깝게 느껴져야 한다.
- 하지만 실제 사용성은 운영 도구처럼 명확해야 한다.
- 장식보다 정보 위계가 우선이다.

### 2. 등급, 보상, 진행감이 중심

- 이 서비스의 재미 포인트는 `등급`, `보상`, `기록`, `성장`이다.
- 특히 등급전과 핵심 멤버 정보는 허브에서 매우 중요하게 보여야 한다.
- 단순 리스트형 관리 화면이 아니라 "성장 상황판"처럼 느껴져야 한다.

### 3. 화면마다 역할이 분명해야 함

- 랜딩은 "길드 운영 게임"의 세계관과 진입 경험
- 허브는 "현재 길드 상태와 핵심 액션"
- 멤버는 "캐릭터 관리와 성장"
- 미션은 "퀘스트 보드"
- 로그는 "전투 기록 / 경제 기록 / 활동 리포트"

## 현재 서비스 구조

전체 라우트 구조는 아래와 같다.

- `/`
- `/guilds/[guildId]`
- `/guilds/[guildId]/members`
- `/guilds/[guildId]/missions`
- `/guilds/[guildId]/logs`

공통 레이아웃은 2단계다.

- 글로벌 상단 바: `src/routes/+layout.svelte`
- 길드 워크스페이스 레이아웃: `src/routes/guilds/[guildId]/+layout.svelte`

## 전체 톤앤매너

### 키워드

- Tactical Fantasy
- Guild Command Center
- Reward-driven HUD
- Arcane Glass + Metal Frame
- Ranked Progression

### 원하는 인상

- 차갑고 정교한 시스템 HUD
- 보상과 성장을 강조하는 금속성 UI
- 고급 게임 로비 / 레이드 대기실 / 작전 콘솔 같은 느낌

### 피하고 싶은 인상

- 일반 SaaS 대시보드 느낌
- 너무 귀엽거나 캐주얼한 모바일 게임 느낌
- 과도한 네온 사이버펑크 느낌
- 판타지라고 해서 너무 복잡하고 지저분한 장식 위주 화면

## 컬러 / 스타일 가이드

현재 코드 기준의 핵심 컬러 방향은 아래와 같다.

- 메인 배경: 매우 어두운 네이비 / 슬레이트 계열
- 강조 1: `amber` 계열
  - 보상
  - 등급
  - 주요 승급 정보
- 강조 2: `cyan` 계열
  - 시스템 정보
  - 진행 상태
  - 네비게이션 / 인터랙션
- 강조 3: `rose` 계열
  - 위험
  - 경고
  - 비용 / 소모

원칙:

- 배경은 다크
- 카드와 패널은 반투명 유리 + 금속 프레임 느낌
- 텍스트 대비는 강하게
- 강조색은 의미 기반으로만 사용

## 타이포 방향

- 제목은 세계관과 무게감이 느껴져야 한다.
- 본문은 매우 읽기 쉬워야 한다.
- 숫자와 스탯은 강하게, 라벨은 절제해서 사용한다.
- 대제목, 섹션 제목, 배지, 스탯 숫자, 카드 메타 정보의 위계를 명확히 분리해야 한다.

## 모션 방향

모션은 필수다. 단, 장식용보다는 피드백용이어야 한다.

필요한 모션:

- 페이지 진입 시 섹션 단위 `fade + slight rise`
- 카드 hover 시 `lift + glow`
- 등급 강조 카드 hover 시 `sheen` 또는 미세한 하이라이트
- 버튼 hover / active 상태 차별화
- 모달 열림 / 닫힘의 일관된 전환
- 보상 상자나 등급전 결과처럼 의미 있는 액션에만 강한 연출

피해야 할 모션:

- 화면 전체에서 계속 움직이는 과한 파티클
- 모든 카드에 동일한 반복 애니메이션
- 사용 중 피로를 주는 깜빡임

## 공통 레이아웃 설명

### 1. 글로벌 상단 바

파일:

- `src/routes/+layout.svelte`

역할:

- 브랜드 인식
- 로그인 유저 상태 표시
- 로그아웃 진입

현재 요소:

- 좌측 엠블럼
- 브랜드명 `RPG Guild`
- 보조 카피 `Guild Operations Console`
- 우측 유저 프로필 / 로그인 상태 / 로그아웃 버튼

디자인 요구:

- 상단 바는 일반 웹 내비게이션이 아니라 "항상 켜져 있는 길드 HUD"처럼 보여야 한다.
- 브랜드는 텍스트보다 엠블럼 중심이 강해야 한다.
- 프로필 칩은 플레이어 상태 패널처럼 보여도 좋다.

### 2. 길드 워크스페이스 헤더

파일:

- `src/routes/guilds/[guildId]/+layout.svelte`

역할:

- 현재 워크스페이스 진입 상태 전달
- 길드 내부 메뉴 전환

현재 메뉴:

- 허브
- 멤버
- 미션
- 로그

디자인 요구:

- 일반 탭바가 아니라 "작전 탭" 같은 인상을 주면 좋다.
- 선택 상태는 매우 분명해야 한다.
- 모바일에서 가로 스크롤이 자연스러워야 한다.

## 화면별 설명

## 1. 랜딩 페이지

파일:

- `src/routes/+page.svelte`

### 화면 목적

- 서비스 첫 진입
- 세계관과 사용 목적 설명
- 로그인
- 길드 생성 또는 초대 코드 참가

### 주요 영역

1. 히어로 섹션
- 큰 카피
- 서비스 핵심 설명
- 3개의 시스템 요약 HUD

2. 인증 패널
- 구글 로그인 버튼
- 인증 상태 로딩

3. 진입 모드 전환 패널
- `길드 참가`
- `길드 생성`

4. 기능 소개 카드 3개
- Mission Control
- Roster HUD
- Reward Loop

### 디자인 요청 포인트

- 랜딩은 단순 소개 페이지보다 "게임 로비"처럼 보여야 한다.
- 좌측은 브랜드 경험, 우측은 즉시 액션 구조가 명확해야 한다.
- 초대 코드 입력은 진입 장치처럼 느껴져야 한다.
- 생성 모드는 "새 길드 창설"의 의식을 강조해도 좋다.

## 2. 길드 허브

파일:

- `src/routes/guilds/[guildId]/+page.svelte`

### 화면 목적

- 길드의 현재 상태를 한눈에 보여주는 메인 대시보드
- 핵심 액션 진입점 제공

### 주요 영역

1. 길드 히어로 배너
- 길드 이름
- 길드 설명
- 인라인 편집
- 멤버 수 / 전체 보유 골드 / 평균 레벨 / 최고 등급 멤버

2. 우측 액션 패널
- 초대 코드 복사
- 상점 관리
- 보상 확률 설정
- 길드 탈퇴

3. 길드 운영 정보 카드
- 생성일
- 보상 상자 확률 / 최대 보너스

4. 핵심 멤버 카드
- 등급 우선 정렬
- 등급 아이콘
- 스테이지
- 등급명
- 칭호
- 현재 골드
- 등급전 진입 가능 여부

### 디자인 요청 포인트

- 허브는 이 프로젝트에서 가장 중요하다.
- "길드 본부 메인 스크린"처럼 보여야 한다.
- 등급 정보는 매우 중요하므로 눈에 띄어야 한다.
- 핵심 멤버 카드는 단순 리스트가 아니라 "대표 전력" 같은 느낌이 필요하다.

## 3. 멤버 페이지

파일:

- `src/routes/guilds/[guildId]/members/+page.svelte`

### 화면 목적

- 캐릭터 생성 / 수정 / 삭제
- 출석 체크
- 상점 사용
- 등급전 진입

### 주요 영역

1. 상단 개요
- 캐릭터 수
- 상점 아이템 수
- 오늘 출석 완료 수

2. 캐릭터 생성 패널
- 이름
- 직업
- 등급
- 설명

3. 캐릭터 카드 그리드
- 직업 배지
- 등급 아이콘 / 등급명 / 칭호
- 이름 / 설명
- 골드
- 레벨
- 연속 출석
- 출석 버튼
- 상점 이용
- 등급 도전
- 수정 / 삭제

4. 캐릭터 수정 모달

5. 등급전 모달 진입

6. 상점 모달 진입

### 디자인 요청 포인트

- 이 화면은 "멤버 관리"가 아니라 "파티 슬롯 관리"처럼 보여야 한다.
- 캐릭터 카드가 서비스의 세계관을 가장 직접적으로 드러내는 부분이다.
- 등급, 레벨, 직업, 골드는 한눈에 구분 가능해야 한다.
- 높은 레벨 / 높은 등급 캐릭터는 시각적 차등이 필요하다.

## 4. 미션 페이지

파일:

- `src/routes/guilds/[guildId]/missions/+page.svelte`

### 화면 목적

- 퀘스트 생성
- 퀘스트 수정 / 삭제
- 오늘 완료 상태 확인
- 멤버 선택 후 보상 지급

### 주요 영역

1. 상단 개요
- 남은 퀘스트 수
- 오늘 완료 수
- 참여 가능한 멤버 수

2. 퀘스트 생성 / 수정 폼
- 퀘스트명
- 설명
- 보상
- 유형 선택
  - solo
  - party
  - assigned
- 배정 캐릭터
- 일회성 여부

3. 퀘스트 카드 리스트
- 유형 / 상태 / 완료 여부
- 편집 / 삭제
- 완료 처리 진입

4. 완료 처리 모달
- 캐릭터 선택
- 오늘 이미 완료한 캐릭터 표시
- 보상 지급

5. 보상 상자 모달
- 랜덤 박스 발견
- 보너스 공개 연출

### 디자인 요청 포인트

- 미션 화면은 가장 "게임다운" 느낌이 강해야 한다.
- 일반 태스크 리스트보다 퀘스트 보드에 가까워야 한다.
- 완료 처리 플로우는 "보상 분배 패널"처럼 보여야 한다.
- 보상 상자 연출은 시그니처 장면으로 만들고 싶다.

## 5. 로그 페이지

파일:

- `src/routes/guilds/[guildId]/logs/+page.svelte`

### 화면 목적

- 길드 활동 기록 조회
- 멤버 기준 필터
- 타입 기준 필터
- 검색
- 달력 기반 회고

### 로그 타입

- 미션 로그
- 등급전 로그
- 아이템 사용 로그

### 주요 영역

1. 상단 개요 카드
- 전체 건수
- 미션 건수
- 등급전 건수
- 사용 건수

2. 뷰 전환
- 타임라인
- 달력 보기

3. 필터
- 멤버 선택
- 로그 타입 선택
- 검색어 입력

4. 타임라인 보기
- 날짜 그룹
- 로그 카드
- 최근 7일 활동 추이 차트

5. 달력 보기
- 월 이동
- 월간 활동 건수
- 월별 타입 분포 차트
- 날짜별 셀
- 선택 날짜 상세 패널

### 디자인 요청 포인트

- 로그 화면은 "히스토리 리포트"처럼 보여야 한다.
- 단순 리스트가 아니라 회고 대시보드 성격이 강해야 한다.
- 날짜 탐색과 유형 구분이 매우 쉬워야 한다.
- 차트는 과한 BI 도구 느낌보다 게임 리포트 보드처럼 표현되면 좋다.

## 모달 설명

## 1. 등급전 모달

파일:

- `src/lib/components/MiniGameModal.svelte`

### 역할

- 캐릭터 등급 시험 진행
- 현재 등급, 목표 등급, 보상, 패널티 표시
- 미니게임 결과 표시

### 주요 특성

- 등급별 시험 종류가 다름
- 단계가 높아질수록 어려워짐
- 최고 등급 도달 시 별도 완료 상태 표시

### 디자인 요청 포인트

- 이 모달은 일반 폼 모달이 아니라 "승급 시험장"처럼 보여야 한다.
- 현재 등급과 목표 등급 대비가 매우 중요하다.
- 결과 화면의 성취감이 강해야 한다.

## 2. 상점 관리 / 상점 사용 모달

파일:

- `src/lib/components/ShopManager.svelte`

### 역할

- 길드 보상 아이템 관리
- 멤버가 골드로 아이템 구매

### 디자인 요청 포인트

- 전리품 교환소, 보급소 같은 느낌이 좋다.
- 가격과 아이템 가치가 잘 보여야 한다.

## 정보 우선순위

디자인 작업 시 정보 우선순위는 아래 순서를 따른다.

1. 현재 상태
- 길드 상태
- 멤버 상태
- 등급
- 미션 완료 여부

2. 핵심 액션
- 생성
- 저장
- 완료
- 등급전
- 구매

3. 성과 / 보상
- 골드
- 보너스
- 승급
- 기록

4. 보조 정보
- 설명
- 생성일
- 부가 텍스트

## 반응형 요구사항

- 모바일에서도 정보 구조가 무너지면 안 된다.
- 특히 다음 요소는 모바일 우선 검토 필요:
  - 상단 HUD
  - 탭 네비게이션
  - 멤버 카드 액션 버튼
  - 미션 완료 모달
  - 로그 달력 셀

원칙:

- 모바일은 "압축"이 아니라 "우선순위 재배치" 방식으로 접근
- 데스크톱은 밀도감 있게
- 모바일은 조작 가능성 우선

## 외주 산출물 요청안

디자인 외주에는 아래 산출물을 요청하는 것을 권장한다.

### 필수

- 전체 서비스 스타일 가이드 1세트
- 전체 화면 고해상도 시안
- 모바일/데스크톱 반응형 시안
- 공통 컴포넌트 세트
- 컬러 / 타이포 / 상태값 규칙

### 권장

- 핵심 인터랙션 모션 가이드
- 모달 전환 가이드
- 카드 hover / active / selected 상태 정의
- 로그 차트 / 달력 컴포넌트 상태 정의

## 우선순위 제안

외주 범위를 나눈다면 아래 순서를 권장한다.

### 1차 우선

- 길드 워크스페이스 헤더
- 랜딩
- 길드 허브

### 2차 우선

- 멤버 페이지
- 미션 페이지
- 등급전 모달

### 3차 우선

- 로그 페이지
- 상점 / 관리 모달
- 빈 상태 / 로딩 / 예외 상태
